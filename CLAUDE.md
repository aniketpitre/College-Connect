# CollegeConnect

A college ERP for an Indian undergraduate college with a built-in AI help desk
(CollegeConnect AI: cited answers from official documents, in English, Hindi and Marathi).

## Plans — read these before starting ERP work
- [docs/erp/01-product-spec.md](docs/erp/01-product-spec.md): roles and logins, every module's features, unique features, confirmed decisions (D1–D7).
- [docs/erp/02-implementation-plan.md](docs/erp/02-implementation-plan.md): architecture, data model, auth/RBAC design, API outline, phases and the PR list.

Build order: **core ERP first (Phases 0–2), then other features incl. the unique ones (Phases 3–4), CollegeConnect AI last (Phase 5)**. The public help desk was replaced by the home page after Phase 5: CollegeConnect AI is for signed-in people only (`/assistant/ask`; `/query` needs a sign-in too). Work follows the phase/PR order in the implementation plan. If a change departs from the plan, update the plan in the same PR.

## Workflow rules
- **Open a pull request for every code-level change.** Never leave pushed code without a PR.
- One PR per plan item where possible; keep `main` deployable.
- Never commit secrets (`.env`, connection strings, API keys). They live in Vercel environment variables and the gitignored `backend/.env`.

## Stack and layout
- `frontend/`: React + TypeScript + Vite, React Router, TanStack Query. `src/app/` (routes in `App.tsx`, portal shell `AppLayout.tsx`, public pages), `src/features/<module>/` (help desk, analytics, users, …), `src/components/` (DataTable, MoneyText, StatusBadge, ConfirmDialog, Modal, EmptyState), `src/lib/` (`api.ts` with `apiFetch`/`ApiError`, `money.ts`, types), `src/i18n/` (en/hi/mr strings; `home.ts` for the home page). Routes: `/` home page (the college site with Login; its data from the public `GET /setup/public`; CollegeConnect AI needs a sign-in), `/apply` (admissions), `/login`, `/login/2-step`, `/forgot-password`, `/reset-password#<token>`, `/setup`, `/verify/:code`, `/app/*` portals (`/app/account`, `/app/profile`, `/app/welcome`, `/app/students[/:id|/import|/promote]`, `/app/fees[/setup|/students/:id|/collect/:id|/reports|/opening|/online]`, `/app/my-fees`, `/app/notices[/:id]`, `/app/timetable[/:id]`, `/app/attendance[/take/:slotId/:date]`, `/app/exams[/marks/:divisionId/:subjectId|/sessions/:id]`, `/app/certificates`, `/app/messages`, `/app/application` (applicant), `/app/admissions[/applications/:id]`, `/app/library`, `/app/hostel`, `/app/placement`, `/app/grievances`, `/app/leave`, `/app/staff`, `/app/reports`, `/app/mentoring`, `/app/scholarships`, `/app/api-keys`, `/app/knowledge`, `/app/approvals`, `/app/audit`, `/app/exports`, `/app/setup`, `/app/users`, `/app/analytics`). Student-facing strings live in `src/i18n/` (`auth.ts`, `account.ts`, `student.ts`, `privacy.ts`, `portal.ts`, `notices.ts`, `timetable.ts`, `attendance.ts`, `marks.ts`, `certificates.ts`, `parent.ts`, `messages.ts`, `admissions.ts`, `campus.ts`, `grievance.ts`, `scholarships.ts`, `assistant.ts`, `home.ts`, `nav.ts`); the language choice is shared app-wide via `useLanguage()` in `src/lib/language.ts`. Nav items are gated by permission (`hasPermission`).
- `backend/`: FastAPI, Python 3.12. `app/core/` (settings, MongoDB client + `run_in_transaction` + index registry, error format), `app/modules/<module>/` (router, schemas, services), `app/rag/` (help desk AI). All routes are mounted under `/api/v1`; the old `/api/...` paths stay as hidden aliases for the live help desk.
- ERP modules so far: `setup/` (college structure), `students/` (records, corrections, documents, import, promotion), `onboarding/` (first sign-in, privacy consent), `fees/` (ledger, structures, demands, approvals, scholarships, receipts + PDF, cancellations/refunds, opening balances, reports), `portal/` (student `/me/*`: home cards, my fees, statement PDF), `notices/` (audiences, schedule/expiry, translations, PDF, chunked email), `auditlog/` (read-only `/audit`), `exports/` (approved CSV exports, a student's own data as JSON), `timetable/` (per class and term, clash checks, one-day changes), `attendance/` (per-lecture records, 48-hour edits then HOD, exemptions, percentages, daily alert cron), `marks/` (assessment schemes, marks sheets and their workflow, University Upload Guard + export), `exams/` (exam sessions, forms, eligibility, seat numbers, hall ticket PDF), `results/` (import, SGPA/CGPA, backlogs, revaluation, statement PDF), `certificates/` (types, requests, promised dates, escalation, numbered PDFs with QR, TC → read-only login), `dashboard/` (staff home sections by role; `overview.py`: Principal and Accounts overviews), `jobs/` (the one daily cron `GET /cron/daily`, needs `CRON_SECRET`), `parents/` (linking, sign-in code, consent; `guard.py` lists what a parent may call, with the child picked by the `X-Child` header), `payments/` (Razorpay checkout, webhook, receipts, reconciliation; `RAZORPAY_*`), `messaging/` (email/SMS/WhatsApp templates in en/hi/mr, preferences, queue, delivery log), `admissions/` (cycles, enquiries, applicant sign-in and application, scrutiny; `merit.py` rounds, confirmation → student + login + fee demand, cancellation with refund rules; `guard.py` keeps applicants to their application), `library/` (catalogue, ISBN lookup, issue/return, fines into the fee ledger, reservations, overdue reminders), `hostel/` (blocks, rooms, allotment with yearly fee, out-passes, complaints, mess menu), `placement/` (drives with CGPA/backlog eligibility, registrations with resume, rounds, NAAC/NIRF stats), `grievance/` (categories, anonymity, time limits with escalation, ICC-only sensitive cases, feedback), `staff/` (staff records and qualifications, leave types and computed balances, HOD/Principal approval, workload), `reports/` (NAAC metrics with AQAR tables, gaps and evidence in `naac.py`; AISHE, NIRF, APAAR checks/import and ABC credit export in `government.py`), `mentoring/` (early-warning rules worked out daily into `risk_flags` with the reasons, mentor assignment, counselling notes; only mentor/HOD/Principal ever see it), `eligibility/` (scholarship scheme rules, each student's checker, Accounts' candidates), `integrations/` (API keys with read scopes, the open API under `/api/v1/open`, its own OpenAPI docs); `knowledge/` (the help desk's documents in MongoDB: `kb_documents`/`kb_chunks`/`kb_meta`, bundled `index.json` copied in on first change, notices indexed for their own audience, re-index), `assistant/` (`POST /assistant/ask` for signed-in people; `access.py` decides which chunks each person may be answered from; `record.py` adds excerpts of a student's/parent's own fees, certificates, attendance and marks in their language, never logged; `staff.py` answers staff questions with four pre-defined, permission-checked queries, `POST /assistant/staff`); `deadlines/` (deadline radar: dates found in notices, confirmed by staff, home cards and reminders); the knowledge-gap loop is `helpdesk/analytics.gaps` + `/kb/gaps*`; the full export (collections in pages + data dictionary; secrets left out) is `exports/full.py`, restored with `python -m scripts.restore_export`; the no-dues check before a TC is `certificates.service.dues` (fees, library, hostel). Free tiers (MongoDB M0, Vercel Hobby): keep documents compact, make PDFs on demand, keep requests short. Private files go through `app/core/files.py`; money helpers (paise parsing, Indian format, amount in words) in `app/core/money.py` and `frontend/src/lib/money.ts`.
- Offline attendance: `frontend/public/sw.js` (app shell) and `src/lib/offline.ts` (IndexedDB cache + outbox); "today" on the server comes from `app/core/clock.py` (India time).
- Auth and roles: `app/core/auth.py` (cookie sessions, `require(P.X)` dependency), `app/core/rbac.py` (roles → permissions; add new permissions there). Every change of record calls `app/core/audit.record`.
- API errors always look like `{"error": {"code", "message", "field?"}}`: raise `AppError` from services.
- `backend/knowledge/<category>/`: the bundled help-desk documents; rebuild `app/data/index.json` with `python -m scripts.ingest` (or `--no-embed`). It is copied into MongoDB on the first change from "Help desk documents" (`/app/knowledge`); after that the database is the knowledge base. Search takes an `allowed` filter (`rag/store.py`): `assistant/access.chunk_filter(ctx)` for signed-in people (applicants: `public_only()`). Notice translations: `rag/generator.translate_notice`.
- `vercel.json`: frontend and backend deployed as two services on one domain (`/api/*` → backend); the web service falls back to `index.html` so deep links work. In dev, Vite proxies `/api` to `localhost:8000`.

## Commands
- Backend: `cd backend && pip install -r requirements-dev.txt && uvicorn app.main:app --reload --port 8000`
- Backend checks (same as CI): `ruff check . && ruff format --check . && mypy app scripts && python -m pytest -q`. Database tests need a MongoDB replica set: `docker run -d -p 27017:27017 mongo:7 --replSet rs0` then `docker exec <id> mongosh --eval "rs.initiate()"`; without one they are skipped.
- Frontend: `cd frontend && npm install && npm run dev` · checks (same as CI): `npm run lint && npm test && npm run build`
- Demo data (never production): `cd backend && MONGODB_DB=collegeconnect_dev python -m scripts.seed_demo --erp` (needs an empty database; prints the demo logins).
- Restore a full export into an empty database: `cd backend && python -m scripts.restore_export <zip> --db <new-name>` (checks counts and prints the ledger total; drill steps in `docs/erp/runbooks/backup-restore.md`).
- Help-desk evaluation (plan 5.9): `cd backend && python -m scripts.eval_helpdesk` (cases in `eval/helpdesk_eval.json`, EN/HI/MR; Hindi/Marathi are scored only with `ANTHROPIC_API_KEY` or embeddings).
- Load test (never production): `cd backend && MONGODB_DB=<test db> python -m scripts.loadtest prepare --students 2000`, start the server with `LOGIN_LIMIT_PER_IP=1000000 COOKIE_SECURE=false`, then `python -m scripts.loadtest run --url http://localhost:8000`.
- Security: `docs/erp/security-review.md` (OWASP review, college to-dos). The client IP comes from `X-Real-IP` (never `X-Forwarded-For`); localhost CORS only when `ALLOW_LOCALHOST_ORIGINS` (default on, off on Vercel); the production frontend build carries a CSP (`vite.config.ts`), so new external scripts/styles must be added there.
- End-to-end (CI job `e2e`): seed a fresh database as above, then `cd frontend && npx playwright test` with the same `MONGODB_DB` (set `E2E_PYTHON` / `E2E_CHROMIUM` to use a local venv or Chromium).

## Conventions
- Money is stored as integer paise; balances are computed from ledger entries, never edited in place; corrections are reversal entries with a reason.
- Every student-facing string exists in en/hi/mr.
- A student or parent must only ever reach their own (or their linked child's) data; enforce in the backend service layer and test it.
- Environment variables for the app use the `RAG_` prefix for AI settings (plain `CLAUDE_*` names clash with Claude Code's own variables).
